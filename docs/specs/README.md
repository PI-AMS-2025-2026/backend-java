Explicação simples sobre os arquivos `specs`:

- O que são: documentos curtos que descrevem uma funcionalidade antes de ser implementada.  
- Objetivo: alinhar produto, time e testes — reduzir dúvidas e retrabalho.  
- Estrutura típica: nome da feature, data/branch, descrição de entrada; histórias de usuário (P1/P2/P3) com cenários em Given/When/Then; casos de borda; requisitos funcionais; entidades (se houver); critérios de sucesso; suposições.  
- Como usar: quem pede escreve a necessidade; o autor transforma em histórias prioritárias e cenários testáveis; time revisa antes de começar a implementar.  
- Boas práticas: priorize slices pequenos e testáveis (P1 primeiro), marque dúvidas como "NEEDS CLARIFICATION", e mantenha cada história independente.  
- Resultado esperado: um documento claro e verificável que serve de contrato para desenvolvimento e testes.
